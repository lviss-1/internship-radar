# Internship Radar

Finds new internship postings shortly after they go live, scores each one against two resumes with Claude, and posts the good matches to a private Discord channel. A person reviews every match and applies by hand; nothing is ever submitted or sent automatically.

## How it works

Every ~30 minutes a GitHub Actions run:

1. **Fetches** the [SimplifyJobs Summer 2027 feed](https://github.com/SimplifyJobs/Summer2027-Internships) (`listings.json` on the `dev` branch) and the public job boards in `config/watchlist.yaml` (Greenhouse, Lever, Ashby).
2. **Normalizes** everything into one `Posting` model and merges duplicates: when Simplify and an employer's board list the same job, the board copy wins (it has the real publish time and description).
3. **Filters** for free: intern-level titles, Spring/Summer/Fall 2027, location (NYC area, NJ, CT in person; US remote; other US states only if relocation is offered), and drops non-US, quant finance and hardware roles.
4. **Dedupes** against IDs already handled, stored on the `state` branch.
5. **Scores** each new match with Claude Haiku (strict JSON, validated with pydantic): which resume fits, a 0-100 score, reasons, gaps, relocation and eligibility flags.
6. **Drafts** resume edits, a cover note and a referral message with Claude Sonnet for scores of 80+. Any suggested edit that doesn't quote a real line of the resume is dropped.
7. **Delivers** to Discord: 60+ posts, 80+ also mentions the owner (silently during quiet hours, 01:00-07:00 ET). Lower scores are recorded by ID only.

Problems go to a separate errors channel, at most once per 6 hours per problem, with a "recovered" note when they clear. A heartbeat posts once a day after 08:00 ET with spend and detection-lag numbers.

### Where things live

| What | Where |
|---|---|
| Code | `src/radar/` (`sources/`, `normalize`, `filters`, `state`, `scoring`, `drafts`, `delivery`, `discord`, `alerts`, `main`) |

## Setup

### GitHub secrets

Add with `gh secret set NAME` (values are never committed or logged):

| Secret | Purpose |
|---|---|
| `DISCORD_WEBHOOK_MATCHES` | Webhook for the matches channel |
| `DISCORD_WEBHOOK_ERRORS` | Webhook for alerts and the heartbeat |
| `DISCORD_PING_USER_ID` | Numeric Discord user ID to mention on 80+ scores |
| `ANTHROPIC_API_KEY` | Claude API key |
| `RESUME_SWE_TEXT`, `RESUME_PM_TEXT` | Plain-text resumes (`gh secret set RESUME_SWE_TEXT < swe.txt`) |
| `HEALTHCHECK_PING_URL` | healthchecks.io ping URL (optional but recommended) |

### Triggering (cron-job.org)

GitHub's built-in scheduler is in the workflow but has been unreliable for this repo, so an external cron starts runs:

1. Create a **fine-grained token** on GitHub: only this repository, permission **Actions: Read and write**, nothing else. Note its expiry date.
2. On cron-job.org create a job: every 30 minutes, `POST https://api.github.com/repos/<owner>/internship-radar/actions/workflows/radar.yml/dispatches` with body `{"ref":"main"}` and headers `Authorization: Bearer <token>`, `Accept: application/vnd.github+json`, `X-GitHub-Api-Version: 2022-11-28`. A test run should return **204**.

Extra triggers are harmless: runs queue one at a time and state prevents re-posting.

### Alarm (healthchecks.io)

Create a check with period **30 min** and grace **90 min**, add the Discord integration pointing at the errors channel, and store its ping URL as `HEALTHCHECK_PING_URL`. Successful runs ping it, failed runs ping `/fail`; if pings stop for ~2 hours it alerts.

## Operations

| Task | How |
|---|---|
| Is it running? | `gh run list --workflow radar.yml --limit 10` (new run every ~30 min), the healthchecks.io dashboard, or the daily heartbeat |
| Runs stopped and the alarm fired | Check cron-job.org's history: 401 means the token expired or is wrong; 403/404 means it lost access. Create a new token and paste it into the job |
| "Board … has failed N runs in a row" | The company likely moved job systems. Run `uv run python scripts/probe_boards.py`, review `config/watchlist.yaml`, commit |
| Claude prices changed | Update `pricing` in `config/settings.yaml`; the spend ledger uses these numbers |
| Next season | Point `sources.simplify.url` at the new SimplifyJobs repo and update `filters.seasons` |
| Pause the radar | Disable the cron-job.org job (and the workflow: `gh workflow disable radar.yml`) |
| Try it locally | `uv run radar --dry-run` fetches and filters without calling Claude, posting or writing state |

## Costs and safeguards

- Scoring costs about $0.001 per posting and drafts about $0.04 each; a typical month is estimated at a few dollars.
- Every Claude call is checked against a daily call cap and a **$15 monthly hard cap** before it is made (assuming the call's worst case). A warning posts when spend passes **$10**. At the cap, new matches post unscored and silent until the month resets.
- The ledger is an estimate from configured prices. Also set a monthly spend limit in the Anthropic Console as a backstop.
- Actions logs are public, so runs log counts and posting IDs only: never resume text, job descriptions or model output.
- Job descriptions are treated as untrusted data in the prompts; the model has no tools and must return schema-valid JSON.
- Description fetching only follows public `https` URLs and re-checks every redirect.
